这是一段用于检查中文正文排版的长文本。系统的缓存层与字体子集流程在这一轮里都不改动，
只调整字体族、字号、行距与栏宽。目标不是让页面变得更“古典”，而是让中文长阅读更舒服：
既不显灰，也不过细，行与行之间留出可以呼吸的余地，同时避免每行字数过多。

Astro 7 的构建流程会把 Markdown 编译为静态 HTML，因此排版规则只依赖 CSS 与字体文件。
WebSocket、RVC3-python 这类混排字符串，需要确认中文 Serif 与 Latin 回退之间的字高与字重
没有明显跳变；“一点薄荷 MintBlog”、“GitHub”、“2026.09.29”同样是必须检查的样本。

## 小节标题

正文的第二段用来检查段落间距。列表、引用块与代码块也需要保持同样的节奏，不要让某一种元素
突然变得过密或过松。

- 列表项一：检查项目符号与文字的间距
- 列表项二：检查行高与段间距是否一致
- 列表项三：检查 `inline code` 的字号与基线

> 引用块的语气应当比正文安静一点，但不能灰到难以阅读。

```js
const fonts = ["content", "ui", "mono"];
console.log(fonts.join(" / "));
```

### 更深一层的小标题

**加粗的中文**与 **Bold Latin** 一起检查字重跳变，`fixed-width` 保持等宽。

最后一段用来确认长段落的收尾：行距过松会显得松散，过紧则会在中文里堆积笔画。
